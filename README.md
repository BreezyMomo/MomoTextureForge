# Momo Texture Forge

网页图形与纹理创作工具，支持公式、图片和 SVG 资源、节点组合、程序动画与多格式导出。编辑和渲染在浏览器中完成，可通过本地服务使用，也可构建为离线 HTML。

**在线访问：[Momo Texture Forge](https://breezymomo.github.io/MomoTextureForge/)**（首次完成 GitHub Pages 部署后可用）。

## 快速开始

开发环境需要 Node.js 22 或更高版本，浏览器推荐桌面 Chrome 或 Edge，需支持 WebGL2。

在仓库根目录执行：

```sh
npm ci
npm start
```

打开 http://127.0.0.1:8787/ 。Windows 也可双击 `start.bat` 启动服务。指定端口：

```sh
npm start -- --port 8799
```

浏览器中的图库、图形列表和草稿按访问地址保存；更换端口、浏览器或打开离线文件时，这些数据可能不共享。重要资源和作品请导出文件备份。

## 制作流程

1. 打开顶部“图形库”，选择资源并添加到“图形列表”；也可通过“创建资源”制作自己的图形。
2. 在图形列表中点击“＋ 添加”，将资源作为节点加入画布。
3. 在左侧节点树选择图形或组合，在右侧调整图形、变换/排列、动画和合成。
4. 使用播放、单独预览和“平铺检查”检查效果。
5. 通过“文件 → 保存项目”保存可继续编辑的作品，通过“导出…”生成图片、序列帧或矢量轮廓。

## 图库与资源

| 位置 | 用途 |
| --- | --- |
| 图形库 | 管理可重复使用的内置、自建和远程资源，支持搜索、筛选、批量添加与导出 |
| 图形列表 | 存放当前浏览器中跨作品使用的常用资源副本，新建作品不会清空 |
| 画布节点 | 作品中的编辑实例，可独立调整，不自动修改图库和其他实例 |

“创建资源”提供图片、导入文件、公式三个页签。图片编辑支持去除背景、提取颜色、轮廓重建、自动居中、缩放、旋转、颜色替换和转为 SVG 路径；复杂图像可先在专业图像软件中处理。

图片编辑过程中可对比原图。保存或导入图库时，有处理的位图固化为处理结果，原图和处理恢复参数不随资源保存；SVG 保留矢量源文件。

图形列表中点击缩略图可进入试编辑，“添加到作品”才创建画布实例。调整后的内容可另存或明确更新到图形列表；删除列表条目不会删除图库原件。项目保存携带画布依赖，不包含整个常用图形列表。

资源包携带公式、图片及所需依赖，适合备份与分享。远程图库支持多个 HTTP(S) 目录订阅，远程服务需允许跨域；下载资源后可离线使用。

内置图库提供 284 个基础图形、纹样、噪声与矢量资源；其他图形可从独立图库导入。内置图形的配置及扩展方式见[图形定义说明](PATTERN_DEFINITIONS.md)。

详细说明：[本地图形库](LOCAL_GRAPHICS_LIBRARY.md) · [资源包格式](RESOURCE-PACK.md) · [远程图库与本地管理器](REMOTE_LIBRARIES.md)

## 搭建自己的图形库

图库可作为独立的静态目录维护和分享，无需动态后端。首次生成需要本仓库及 Node.js 22 或更高版本；使用生成的管理器和订阅图库无需安装 Node.js。

1. 在编辑器的“图形库”中勾选资源，点击“导出资源”，保存为 ZIP 文件。这里需要工具导出的正式资源包，不能直接使用普通图片压缩包。
2. 在本仓库根目录安装依赖并生成图库，将输入路径替换成实际导出的 ZIP：

   ```sh
   npm ci
   node build-remote-library.mjs --input "图库.zip" --out "remote-library" --name "我的图形库"
   ```

3. 打开输出目录中的 `library-manager.html`，使用桌面 Chrome 或 Edge 选择 `remote-library` 文件夹并授权读写，即可导入更多资源、编辑分类和标签、移除资源。本地管理无需启动服务。
4. 将整个 `remote-library` 目录部署到 HTTPS 静态网站或 CDN。服务器需为 `index.json`、资源 ZIP 和缩略图配置跨域访问；公开图库可设置 `Access-Control-Allow-Origin: *`。
5. 在编辑器的“图形库 → 远程图库”中添加名称和目录地址，例如 `https://example.com/my-library/index.json`。使用者按需下载资源，下载后可离线使用。

管理器只修改你授权的本地目录，更新后需自行推送或上传到托管服务。命令行更新应继续使用同一输出目录，以保留图库身份和已有条目；部署更新时先上传资源和缩略图，最后更新 `index.json`。

多包合并、资源版本、目录格式和管理器操作见[远程图库与本地管理器](REMOTE_LIBRARIES.md)。

## 节点、排列与合成

- 图形与组合均可设置位置、尺寸、旋转、轴心、UV 和不透明度；拖动节点树可调整顺序与父级。
- 组合支持网格、环形、随机散布、黄金角螺旋等排列。实例内容可选择整个组合、随机一个子节点或按顺序循环；支持保持设计比例、防堆叠和展开为独立节点。
- 合成支持混合模式、渐变配色、蒙版、反相、色阶和轮廓处理；节点顺序会影响合成结果。
- 节点可开启无缝重复，图形按定义使用原生周期、形状重复或边缘融合。“平铺检查”用于观察接缝，不会自动修复接缝。
- 画布比例在“作品设置”中配置，导出像素尺寸在“导出…”中设置。缩放、棋盘格、辅助框和单独预览不改变最终导出的整个作品。

常用操作：Ctrl/Cmd 单击多选，Shift 连选，Ctrl/Cmd+D 复制，Ctrl/Cmd+G 组合同级节点，Delete 删除，Esc 取消拖动。画布支持框选、平移、旋转、轴心编辑及 UV 操作。

## 动画

支持关键帧、曲线、录制、基础值编辑，以及组合内的时间区间、循环、往返和实例相位。

内置运动使用持续累加的秒数；关键帧使用节点局部 0～1 进度。播放循环不保证公式运动首尾衔接。动态公式可通过运动速度、时间偏移或手动时间控制，序列导出按帧对应的秒数采样。

播放、播放时长和进度条位于预览下方；展开“动画编辑与时间轴”可编辑轨道和曲线。

## 导出

| 形式 | 用途与限制 |
| --- | --- |
| PNG 8/16 位、EXR Half | 单张颜色、高度、法线或自定义 RGBA 输出；高精度输出需要浏览器支持浮点渲染 |
| 逐帧 ZIP、图集、多尺寸 ZIP | 动画序列和不同尺寸的贴图交付 |
| PSD 分层文件 | 保留可拆分的节点层级；复杂合成部分会栅格化，部分基础图形满足条件时可保留形状路径 |
| SVG / PSD 矢量轮廓 | 根据采样透明度生成路径与单色填充，支持孔洞；渐变、柔光和像素级半透明会被简化 |

导出面板提供尺寸、帧数、透明背景、位深及适用格式的轮廓选项。实际尺寸与复杂度受设备、内存和格式限制；矢量轮廓精度取决于采样分辨率和阈值，并非原始解析几何。

## 与 AI 协作

“帮助”菜单提供两个可下载的 Skill：

- **创作 Skill**：辅助判断公式、SVG 或位图路线，制作可导入资源，并通过命令行渲染检查公式。
- **效果指导 Skill**：根据用户需求推荐制作思路，说明如何使用编辑器的排列、合成、动画和导出功能。

需要 AI 推荐具体图形时，在“图形库 → 导出 AI 图形目录”中选择资源或当前筛选结果，生成后复制给 AI 或下载 JSON。目录包含当前资源的名称、分类、参数和能力；Skill 不携带固定图形清单。目录不包含当前作品、图片像素或公式源码，判断视觉效果时可另外提供截图。

命令行用法见 [AI 命令行渲染](AI_AUTHORING_CLI.md)。

## 离线使用

构建单文件：

```sh
npm run build:standalone
```

产物位于 `dist/MomoTextureForge.html`，可直接用浏览器打开；`dist/MomoTextureForge-offline.zip` 用于分享。使用者无需安装 Node.js。本地编辑与导出可离线使用，远程图库刷新和下载需要网络。

分享可编辑作品时，同时提供保存的项目文件；浏览器本地存储不能代替文件备份。

## GitHub Pages 在线访问

生成可部署的单文件网页：

```sh
npm ci
npm run build:pages
```

命令会生成离线 HTML，并同步复制到仓库根目录的 `site/index.html`。`site/` 不在忽略列表中，可以随 Git 提交；每次更新网页前重新运行此命令。将 `site/` 作为网站根目录部署。页面已内嵌脚本、样式、内置图形和导出 Worker，无需部署 Node.js 服务；也兼容 GitHub Pages 的仓库子路径。

本仓库提供 `.github/workflows/pages.yml`。首次使用时，在 GitHub 仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。将配置推送到 `main` 后会自动检查、构建和部署；也可在 **Actions → Deploy GitHub Pages → Run workflow** 手动触发。站点地址以成功部署后的 Actions 输出为准。

公开仓库可使用 GitHub Free 的 Pages；私有仓库需要支持 Pages 的套餐，详见 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。发布网页后，访问者可以获取页面中内嵌的代码和图形资源；仓库私有不代表网页内容私有。

在线版的图库、图形列表和草稿仍保存在访问者自己的浏览器中，不上传到 GitHub，也不与 localhost 或离线 HTML 共享存储。远程图库需另行部署并允许跨域访问。

## 开发

```sh
npm test
npm run validate:definitions
node build-authoring-kit.mjs
```

- `web/`：编辑器、渲染与资源管理，节点工作台入口为 `web/tree-app.js`。
- `web/definitions/`：内置图形索引、定义、公式和公共函数；扩展方式见 [图形定义说明](PATTERN_DEFINITIONS.md)。
- `skills/`：两个 Skill 的维护源；修改后运行 `node build-authoring-kit.mjs` 同步下载包与嵌入内容。
- `tests/`：自动化与浏览器验证工具；浏览器渲染验证独立于 Node.js 单元测试。
- `library-manager/`：本地图库管理页面与逻辑。
- `site/`：可提交的单文件网页及 `.nojekyll` 标记，运行 `npm run build:pages` 更新，由 GitHub Actions 部署。
- `dist/`：生成产物；`test-results/`：本地验证输出。两者及 `node_modules/` 不纳入版本控制。

PSD 编码器的依赖许可位于 `web/vendor/PSD-LICENSES.txt`。需要重新构建编码器时运行 `npm run build:psd-vendor`。
