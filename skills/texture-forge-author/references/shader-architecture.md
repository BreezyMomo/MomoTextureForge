# Shader 职责与扩展规范

<!-- doc-language -->
[简体中文](shader-architecture.md) · [English](shader-architecture.en.md)
<!-- /doc-language -->

把编辑器效果接入游戏引擎时，先遵守[通用接入规则](engine-integration.md)的“优先复用 → 适配 → 补充缺口”顺序。本页约定模块开发与扩展的技术边界。

新增或修改 Shader、生成器、后处理及游戏引擎适配时，先确定职责，再选择现有接口。此规范描述模块边界，不表示所有网页功能已支持 Unity 导出，也不增加当前创作 JSON 未提供的字段或接口。

## 1. 两类职责

| 职责 | 输入与输出 | 例子 |
| --- | --- | --- |
| 图形生成 | 根据坐标、参数、种子和可选时间产生图形；标量公式由宿主转换为图像，RGBA 生成器直接输出图像 | 几何图形、渐变、噪声、水流、火焰 |
| 图像后处理 | 接收已有图像，按参数产生处理后的图像；输入可来自图片、实时 RT 或上游生成模块 | 模糊、扭曲、描边、手绘 |

标准组合为 **算法生成图形／导入图片 → 一个或多个有序后处理 → 图层合成与输出**。遮罩、混合和节点排列由现有组合流程管理；它们不是每个图形都要重新实现的算法。模块可以需要一个或多个渲染步骤，不能为了统一外形强制全部单 Pass。

生成器内部也可以处理它自己的中间纹理；这不意味着当前生成器创作接口支持任意外部图片输入。判断现有能力以实际 schema、目录和支持报告为准。

## 2. 新增模块的边界

- Unity 标准模块随资源保存与分享，供用户阅读使用及 AI 直接复用，见[模块契约](unity-modules.md)。图形的全部自身参数必须映射到可调属性，保留类型、单位、范围和时间语义；图形源码改变时更新并验证实现。自定义资源可携带自己的 `engineShaders.unity`，不要求修改框架名单。普通构建只打包已维护的源码，不在下载时重新翻译。

- 新图形只实现自身生成逻辑和专属参数。可独立应用到其他图像的效果应使用或扩展通用后处理；不要在每个图形 Shader 中复制同一套手绘、模糊或描边算法。
- 新后处理通过明确的图像输入工作，不硬编码上游图形 ID、公式或截图。更换兼容输入后，处理核心仍应可复用。所需通道、辅助输入和静态/动态能力必须声明；不支持的输入明确拒绝，不伪装成支持。
- 同时需要新图形与新后处理时，分开实现、分开验证，再按顺序组合。确属图形自身的内部生成步骤可以保留在生成器中，避免为拆分而拆分。
- 复用现有资源、节点与效果顺序，不为一次示例另建不兼容的项目格式。通用后处理不通过伪造一个绑定特定源图的图库图形来替代。
- 网页交付入口遵守对象范围：通用导出交付渲染结果，不放完整画布转 Unity Shader。已适配图形的生成 Shader 位于图形选择分组，说明仅含基础参数，不代表当前节点或作品；后处理包位于对应效果面板。复杂作品由 AI 结合原生项目与已有模块进行组合、修改和验证。CLI／MCP 保留受限的组合交付，必须逐节点查询实际支持，不把少数已适配模块宣称为通用转换能力。

图形创作分别使用[标量公式](authoring-guide.md)或[RGBA生成器](generator-guide.md)。开发新后处理需在工具实际的效果注册、参数、执行顺序和渲染入口中实现；现有 `.graphic.json` / `.generator.json` 不等于通用后处理插件格式，不发明自定义字段来声称已经接入。

## 3. 输入输出契约

每个模块说明实际使用的坐标、分辨率/宽高比、参数单位、颜色空间、alpha 是直通还是预乘、时间单位及资源归属。跨阶段转换应显式进行，避免重复乘 alpha、重复颜色转换或意外拉伸。透明度和混合按节点组合语义应用，不能因新增阶段重复计算。

静态输入允许缓存；输入、参数或相关时间变化时应更新。动态输入不得暗中冻结为静态图；固定种子和同一输入/参数/时间应可复现。使用中间 RT/缓冲的模块负责尺寸变化、切换、失败与禁用时的资源释放。

这些是契约项目，不是所有模块共享的固定数值。手绘的短边512、Compute/RFloat及特定填充映射属于[手绘后处理](handdrawn-postprocess.md)，不得自动套用到其他新效果。

## 4. 网页与引擎交付分别验收

网页可运行不代表已有 HLSL/Unity 适配。新增可导出的图形或后处理时，同步维护实际支持查询、参数映射、导出包/依赖、运行组件与所需导入器；只声明已实现并验证的范围。[标准模块](unity-modules.md)、[受限组合导出](realtime-shaders.md)和[手绘后处理](handdrawn-postprocess.md)各自按实际能力交付。

不支持的节点、效果、参数或动画应给出原因与路径，不忽略、不替换效果。静态烘焙必须作为明确选择说明，不称为实时实现；手绘旧轻量填充与冻结描边出口不再使用。

验收包括真实默认效果与参数边界、时间/种子、透明输入与宽高比；后处理更换不同输入验证复用，组合后检查顺序、颜色和透明度。涉及运行资源时检查缓存/更新、释放和持久化。结构校验、网页渲染、HLSL编译、目标引擎视觉/播放及 Player/平台验证分别记录，未执行项如实标明。修改内置视觉公式时，另遵守仓库缩略图更新要求。
