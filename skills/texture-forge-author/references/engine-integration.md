# 将编辑器效果接入游戏引擎

<!-- doc-language -->
[简体中文](engine-integration.md) · [English](engine-integration.en.md)
<!-- /doc-language -->

本规则适用于 AI 将 Momo Texture Forge 的图形、图片、后处理、动画及组合效果接入任何游戏引擎，不针对某一种效果。当前可直接交付的模块仅覆盖部分图形和后处理；覆盖范围随工具实际实现变化，不能把网页可显示等同于目标引擎已适配。

## 1. 先读取作品与目标工程

从用户提供的原生项目 ZIP 或明确授权的网页快照读取真实节点、依赖、参数、关键帧和效果顺序，并渲染代表性时刻作为参考。网页操作遵守[快照与连接规则](live-editor.md)，离线文件使用[项目工具](project-tools.md)。不要为获取源码而接入其他页面或读取整个用户图库。

确定目标引擎、版本、渲染管线、使用载体与性能要求。优先使用上下文已知信息，只询问影响实现的缺失项。已有 Unity 包不代表能直接用于其他管线、引擎、UI 或粒子场景。

## 2. 写代码前先查现有模块

先查询实际 Shader 支持报告，检查涉及的图形与后处理，并读取工具已有的 Shader、运行组件、参数映射、依赖和接入说明。Unity 的查询与交付见[已适配图形](realtime-shaders.md)，具体后处理遵守各自技术文档；当前[手绘后处理](handdrawn-postprocess.md)是其中一种实现。

完整作品不支持直接导出时，继续按节点和阶段确认可复用模块，不把整个作品标为“没有 Shader”。MCP 的支持查询和交付使用同一新鲜 `snapshotId`；CLI 对源项目查询。不要凭显示名称、图标或固定清单代替实际能力检查，也不要只看参考截图就从头重写效果。

## 3. 复用、适配、补充的优先级

| 条件 | 应采取的实现 |
| --- | --- |
| 已有模块与目标环境、视觉要求兼容 | 优先直接使用工具提供的 Shader、运行组件、导入器及参数映射，不另写同功能的简化版本 |
| 已有模块覆盖核心算法，但接口、管线或部分能力不匹配 | 以现有源码和输入输出契约为基础适配，保留可用算法、参数语义、许可与署名；补齐必要接口或功能 |
| 工具缺少模块，或已有模块确实不适用 | 说明具体缺口，再根据编辑器实际源码、项目数据和参考结果实现缺失部分；不要重做其他已可复用的模块 |

此优先级同时适用于图形生成、图像后处理及其依赖，不限于手绘。现成包中的示例参数不等于用户调好的参数，必须按项目的变量、路径、单位和动画语义映射实际值。仅有 GLSL 源码时，可将其作为移植依据，不能宣称已存在目标引擎适配。

## 4. 组合完整效果

按原生作品的依赖和执行顺序组合生成模块、图像输入、后处理、遮罩、图层混合和动画。优先连接已有模块，只补充尚未覆盖的排列、时序、合成或其他能力；必要时使用多个 Pass 或运行组件，不能为方便交付强行压成单 Pass。

保留颜色空间、透明度、坐标、尺度、时间单位和资源归属，具体契约见[Shader 职责与扩展规范](shader-architecture.md)。不能静默跳过节点、忽略不支持参数、替换视觉样式，或为通过导出检查修改用户原作品。烘焙、降级和近似需要明确说明；静态帧或静态输入不能冒充完整动态效果。

## 5. 在目标引擎中验收

使用包内正式接入方式，检查真实引擎编译、代表性时刻与动态变化、透明输入和宽高比、参数响应及组合顺序。涉及运行资源时，检查更新、输入切换、释放和资产保存重开。浏览器通过、核心 Shader 编译和目标引擎视觉验证分别记录，未执行项如实说明。

交付时说明哪些模块直接复用、哪些做了适配、哪些是新增实现，以及仍未覆盖或明确烘焙的部分。不得把少数模块交付成功表述为整个编辑器已经支持任意效果一键转换。
