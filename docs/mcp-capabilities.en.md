# MCP editor capabilities

<!-- doc-language -->
[简体中文](mcp-capabilities.md) · [English](mcp-capabilities.en.md)
<!-- /doc-language -->

This document describes current product capabilities. 53 structured MCP tools cover the editor workflows below: projects/nodes, parameters/animation, resource authoring/libraries, import/export, previews/workspaces, remote libraries and host library directories. Workflows checked against existing menus and tutorials are implemented and live-accepted. This is not exhaustive coverage of every input combination, arbitrary code execution, operating-system file dialogs or external engine compilation. All actions reuse native business modules.

## Connection and execution scope

Users explicitly connect each target page. Discover it with `forge_pages`, capture with `forge_capture`, and edit using a fresh snapshotId. Selection is not shared across pages. Projects, graphics-list copies, browser libraries, remote directories and workspace preferences are distinct mutation scopes.

`forge_schema` exposes native operations, blocked patch fields, recipe limits and `editorControls`. Project replacement, existing-file overwrite, remote publishing and deletion must correspond to the user's explicit task. Paths belong to the MCP host. Do not publish or delete real remote data without authorization.

**MCP regression** means actual official SDK, HTTP transport and native execution tests. **Live acceptance** means MCP writes, readback and rendering in a connected real page. Regression does not replace live acceptance. Each applicable upgrade requires the updated Skill/service and a refreshed, reconnected webpage; running pages do not hot-replace their business code.

## Usage constraints

See the [live authoring guide](../skills/texture-forge-author/references/live-editor.en.md) for parameters and operations. Read the relevant state and revision before structured changes. Never reuse old snapshots across user edits. Five end-to-end workflow checks passed: new generator, batch insertion, component insertion, parameters/animation/effects, multi-time rendering, decoded PNG16 and native ZIP. Reopening the ZIP after deleting test originals/list copies retained the exact project hash and rendered correctly; original state was restored. Representative passing tests do not imply exhaustive input coverage. Commit, push and publication remain subject to user instructions.

For animated sketch without baked input textures, query forge_deliver shader-support modes.postprocess / recommendedMode, then explicitly choose postprocess. See [Live individual handdrawn strokes](../skills/texture-forge-author/references/handdrawn-postprocess.en.md) for scope, parameters and runtime resources.
