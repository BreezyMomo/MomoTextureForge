本规则用于 Momo Texture Forge 编辑器及外观预览。设计目标是让作品、当前对象与常用参数容易辨认，并保留面板移动、合并、悬浮、缩放和布局保存能力。

## 1. 层级与颜色

大面积背景使用低饱和、带有方案冷暖倾向的明度层级：工作区、面板、控件和浮层各有用途。相同层级的面板共用标题栏样式，不按“图形列表、节点树、参数面板”分别铺不同颜色。面板移动后仍遵守相同规则。

| 用途 | 使用位置 | 限制 |
| --- | --- | --- |
| 动作色 | 导出等明确的主要操作 | 不把所有可点击元素都做成主按钮 |
| 选中色 | 当前节点、明确选中的对象 | 同时保留边线、标记或状态属性 |
| 导航色 | 当前页签、筛选与键盘焦点 | 焦点使用轮廓，不冒充选中状态 |
| 参数色 | 滑杆、复选框等数值与开关控件 | 不铺满参数面板或分组标题 |
| 功能状态色 | 播放中、录制、关键帧、动画区间 | 含义跨配色保持稳定，配合文字或图标 |

颜色多少不是优化指标。静止且未选中的界面允许克制；需要操作、定位或反馈的地方才增加强调。画布内容、缩略图、作品色板和透明棋盘不受界面配色影响。

主题把颜色分配到可见区域：工作区、同级标题栏、内容卡片、文字、主要操作。不要把所有层级都染成同一种色相，也不要按面板身份或位置给同级面板分配不同颜色。色卡提供搭配基础，“主色等于背景”不是通用规定；实际分配必须验证文字与背景的对比，并用轮廓、标记或文字补充状态。

| 主题 | 工作区 | 同级标题栏 | 内容卡片 | 主要操作 |
| --- | --- | --- | --- | --- |
| 水墨朱砂 | 墨灰 | 蓝灰 | 深灰 | 朱砂 |
| 玄黑鎏金 | 中性炭黑 | 深灰 | 石墨灰 | 暖金 |
| 月白墨青 | 月白 | 雾青 | 象牙白 | 墨蓝 |
| 青瓷流金 | 浅青 | 玉青 | 暖白 | 流金 |
| 青花映月 | 月白 | 天蓝 | 象牙白 | 青花蓝 |
| 敦煌矿彩 | 暖砂 | 石绿 | 米白 | 赭橙 |
| 藕荷雪青 | 藕荷 | 雪青 | 象牙白 | 暖橙 |

浅色主题的大面积底色降低彩度，标题栏保留主题色，内容卡片和输入框采用不同明度；面板与卡片使用可见轮廓，输入框边界至少达到 3:1。不要把深色界面的白色高光边照搬到浅色主题。

每个主题是一个完整搭配，不强制派生深浅两版。主题由用户选择，不随系统外观切换。作品显示区域保留独立背景，周边工具区跟随主题底色；预览色条直接显示实际工作区、标题栏和内容变量。验收看真实工作区的颜色分布，不只看孤立色块。

## 2. 组件结构

- 面板标题保持统一背景，当前标签使用导航反馈。关闭、悬浮等管理按钮采用次要文字色。
- 参数分组用轻微底色、间距和分隔线区分。避免在“面板 → 分组 → 子分组”每层重复增加外框、阴影和彩色标题块。
- 当前图形参数优先展示，整组重置和随机参数放在参数末尾，以次级按钮呈现。单项重置与关键帧按钮保留在对应数值旁。
- 图库卡片突出缩略图、名称和“添加到画布”。加入图形列表、版本与编辑等次级操作放进详情；已加入使用小状态文字，不占据一个不可用的大按钮。
- 空状态、错误和不可用状态必须解释原因或下一步，不能只改变颜色。

按钮按职责分层：节点树的“＋图形”使用动作色实底，“＋组合”使用描边；组织、复制、删除和显示操作采用常驻的轻量文字按钮。画布工具和时间轴视图使用共同底座，当前模式以导航色和底线标记；吸附独立显示开关状态。播放使用图标、文字和明确轮廓，播放中使用时间状态色。关键帧复制/删除在未选中关键帧时禁用，粘贴在没有复制内容时禁用；删除操作只在悬停时使用危险色。所有操作保留可见文字或无障碍名称及键盘焦点提示。

## 3. 交互状态

| 状态 | 表达 |
| --- | --- |
| 默认 | 中性表面与清晰文字 |
| 悬停 | 局部明度或边框变化，避免整块区域跳色 |
| 键盘焦点 | 连续可见的轮廓；不清除可聚焦元素的焦点提示 |
| 选中 / 当前页签 | 轻量填色、边线或下划线，配合 `aria-selected` / `aria-pressed` |
| 播放 | 停止时中性，播放中高亮并显示暂停操作，使用 `aria-pressed` |
| 禁用 | 保留可读性，不能与可操作按钮难以区分 |

关键帧按钮不继承参数行、配色行或开关行的强调色。未设置动画统一使用中性灰色空心菱形；已有动画但当前时刻无关键帧使用金色带中心点菱形；当前时刻有关键帧使用金色实心菱形。外观预览与真实按钮遵守同一规则。

信息与操作入口不能只在鼠标悬停时出现。详情展开、键盘操作、焦点顺序和 Esc 退出必须可用。

## 4. 布局、密度与语言

响应规则以面板可用宽度为依据，不只看浏览器宽度。窄参数面板将标签与滑杆分行，宽面板可将标签、滑杆、数值对齐在一行。参数页签保持单行，空间不足时横向滚动，键盘聚焦的标签应进入可视范围。

浮窗移动手柄与标签分开，缩放手柄放在内容外的底部区域。保留用户保存的布局、参数模块顺序、外观与密度；视觉升级不得自动重置这些偏好。

中英文都要检查真实界面。英文窄屏顶栏、长参数名、弹窗底部按钮和图形名称不能因文字变长而重叠或不可达。

## 5. 外观与实现

提供七个完整主题、九种控件样式与四种页签形态。主题先实时预览，保存后记住；取消恢复原来的完整设置。

采用三层关系：方案色值 → 语义用途 → 组件变量。`web/appearance.js` 派生表面与可读交互色，`web/theme-tokens.css` 定义公共语义，`web/palette-roles.css` 将语义映射到组件。标题栏、分组、当前页签与焦点分别使用 `--ui-panel-header-bg`、`--ui-section-header-bg`、`--ui-tab-active-bg` / `--ui-tab-active-fg`、`--ui-focus-ring`。不要用面板身份或位置选择器赋予新颜色含义。

结构、间距与自适应规则在对应组件样式中维护；修改前先检查已有规则，避免继续叠加相互覆盖的补丁。新文案使用稳定的语言 key，并同步两种语言。

## 6. 验收

文字对比度按实际渲染背景检查，常规文字目标至少 4.5:1。对比度通过只能说明可读，仍须人工检查主次、边框密度和状态是否容易理解。

- 检查默认工作区、合并标签、底部停靠、窄/宽悬浮参数面板；保留布局和作品数据。
- 检查鼠标与键盘、选中与焦点、播放与停止、详情操作和外观预览取消/保存。
- 检查全部完整主题和控件样式，以及四种页签；确认外观预览与真实控件一致。
- 运行 `npm test`、`node tests/workspace-workflow-browser-check.mjs`、`node tests/appearance-browser-check.mjs`、`node tests/grouped-palettes-browser-check.mjs` 与 `node tests/ui-language-browser-check.mjs`。构建后相关浏览器检查加 `--built`。
- 文档截图通过 `tools/capture-docs.mjs` 更新两种语言；运行 `node tools/check-docs.mjs`。
