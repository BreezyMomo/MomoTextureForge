## 通用职责与后续扩展

Shader 按职责分为两类：**图形生成**根据算法、坐标、参数和时间产生图像；**图像后处理**接收已有图像并处理，可复用到图片、实时 RT 或上游生成结果。通常按“生成图形／导入图片 → 有序后处理 → 图层合成与输出”组合。通用后处理独立复用，不在每种图形中复制实现。

新增 Shader 前阅读[职责与扩展规范](../skills/texture-forge-author/references/shader-architecture.md)，其中约定模块边界、输入输出、颜色/alpha/时间/尺寸、资源生命周期与验证。仓库 `AGENTS.md` 和创作 Skill 入口均指向该规范。网页功能与 Unity 导出覆盖分别确认；当前解析出口仅支持已适配图形，通用后处理正式导出目前覆盖手绘，不表示其他网页后处理已支持导出。

## 选择交付方式

| 需求 | 入口 | 得到什么 |
| --- | --- | --- |
| 继续编辑作品或交给AI修改 | 文件 → 保存项目 | 原生项目ZIP，保留节点与依赖，不是Unity材质 |
| 交付已渲染图片/动画 | 导出 → PNG、GIF、EXR、序列或图集 | 像素结果，见[导出教程](08-export.md) |
| 用算法在Unity实时生成图形 | 导出 → Unity 实时 Shader ZIP | 已审查图形与支持组合的代码、参数、导入器和参考图 |
| 让输入图片/RT产生手绘表现 | 导出 → Unity 手绘后处理（ZIP） | 通用后处理核心、输入适配、参数、组件与导入器，可选受支持图形生成输入 |

Shader交付先查询支持，检查具体节点/参数与近似说明，再导出并按包内README和unityImporter导入目标Unity项目。最后验证实际颜色、透明度、动态效果与保存重开。图片烘焙、动态生成和后处理是不同交付方式，不能相互冒充。

## 一套手绘处理流程

使用 **导出 → Unity 手绘后处理（ZIP）**，或 **合成 → 手绘风格 → 下载手绘后处理包**。RGBA 输入统一经过自动轮廓提取和填充，再合成输出；图片、运行时 RT、审核过的生成器共用同一 GPU 核心和组件。不再并列提供轻量填充或冻结边框渲染。

先查询实际支持。界面、CLI、MCP 会报告未实现的原生样式与参数路径，不会删除网页控件来伪装支持。输入方式可选自动、审核过的生成器、明确抓取的静态 RGBA、外部贴图/RT；auto 不暗中冻结未覆盖的动画。抓取的是手绘前原始输入，不是预烘焙描边。

完整接口、原生填充/来源映射、透明度与颜色编码、短边512尺度和持久化说明见[统一后处理](../skills/texture-forge-author/references/handdrawn-postprocess.md)。包包含实际参数、真实手绘前输入、共享 Shader/Compute/运行组件、材质/Prefab 导入器、原始项目和参考图；命名空间与完整性校验支持多包并存。

## 范围与验证

原图、实心、逐笔排线、无填充具有明确原生映射。未实现样式、虚线、顶点选项和非默认向量预处理会阻止导出，不替代或忽略。核心仍是声明的 Rough.js 近似，不声称完整向量/随机流等价。节点透明度在合成后只乘一次。静态输入按版本缓存，RT/生成器动态更新，资源支持释放和重建。需要 Compute/SM4.5/RFloat，生成器另需 ARGBHalf；移动端/Player 尚未验证。

导出成功与真实 Unity 编译、视觉和播放验证分别记录。新包应实际检查半透明输入、长方形尺度、原图/无填充、缓存与切换、资源/容量、Prefab 重开等。

## 旧出口退役与解析 Shader

已有项目数据不变。旧 handdrawn、dynamic-handdrawn、轻量填充/冻结描边 API 返回迁移到 postprocess 的提示；Skill 不再分发旧渲染器。旧测试产物仅是历史证据，不是当前可选导出。

没有手绘后处理的作品仍可使用 **Unity 实时 Shader ZIP** 的[已审查解析图形流程](../skills/texture-forge-author/references/realtime-shaders.md)。解析出口不会悄悄遗漏后处理，也不能替代统一手绘流程。
